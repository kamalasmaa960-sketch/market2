# متجر إلكتروني فاخر — Cloudflare

حزمة بداية عملية لمتجر يجمع المنتجات المادية والرقمية، مع واجهة عامة ولوحة إدارة وD1.

## ما يتضمنه
- واجهة عربية RTL متجاوبة وهوية بنفسجية فاخرة.
- منتجات مادية ورقمية وسلة وطلب عميل.
- لوحة إدارة محمية بتسجيل دخول.
- تعديل اسم المتجر والوصف وبعض بيانات الواجهة.
- إدارة المنتجات والطلبات.
- تسجيل المرتجعات، مع إعادة المخزون فقط إذا كانت الحالة صالحة لإعادة البيع.
- تسجيل الخسائر والتالف والفاقد، وخصم كمية التالف من المخزون.
- المصروفات وتقرير مالي تقديري يخصم تكلفة البضاعة والمرتجعات والخسائر والمصروفات.
- إعداد أول مدير مرة واحدة عبر API.
- صور المنتجات تُعرض من روابط خارجية مباشرة تبدأ بـ HTTPS.

## قبل النشر
هذه نسخة MVP أولية تحتاج إعداد حساب Cloudflare والاختبار على بيانات تجريبية قبل استقبال طلبات حقيقية. بوابة الدفع الإلكتروني غير مفعلة؛ خيارات الدفع الحالية لا تؤكد الدفع تلقائيًا. لا تضع بيانات بطاقات أو أسرار داخل الواجهة.

## النشر من التابلت
1. أنشئي مستودع GitHub جديدًا وارفعي كل محتويات المجلد.
2. من Cloudflare افتحي Workers & Pages وأنشئي Worker متصلًا بالمستودع، أو استخدمي Wrangler من بيئة تطوير.
3. أنشئي قاعدة D1 باسم `luxury_store_db`.
4. انسخي `database_id` الحقيقي إلى `wrangler.toml`.
5. طبّقي ملفات الترحيل بالترتيب `0001_initial.sql` ثم `0002_security.sql` من واجهة D1 SQL Console أو عبر:
   `npx wrangler d1 migrations apply luxury_store_db --remote`
6. أضيفي الأسرار التالية من Worker Settings → Variables and Secrets: `AUTH_SECRET` (سر عشوائي طويل)، `SETUP_KEY` (مفتاح إعداد أولي قوي)، و`ALLOWED_ORIGINS` (نطاق الموقع مثل `https://your-domain.com`). لا تضعي أي سر في GitHub.
8. انشري المشروع، ثم افتحي `/api/health` للتأكد من عمل الخادم.

## إنشاء المدير الأول
أرسلي POST إلى `/api/setup` مرة واحدة فقط مع مفتاح الإعداد:
```json
{"setup_key":"قيمة-SETUP_KEY","username":"owner","password":"كلمة-مرور-قوية-لا-تقل-عن-12-حرفًا"}
```
بعد ذلك افتحي `/admin.html` وسجلي الدخول. لا يمكن إنشاء مدير آخر من endpoint الإعداد الأولي بعد وجود مدير.

## ملاحظات مهمة قبل التشغيل التجاري
- أضيفي صفحات سياسة الخصوصية والاسترجاع والشحن وبيانات التواصل القانونية.
- راجعي الضرائب والفواتير ومتطلبات حماية بيانات العملاء في بلد التشغيل.
- راجعي منطق المرتجعات مع سياسة المتجر: النسخة الحالية تسجل المرتجع وتضيف المخزون تلقائيًا إذا كان صالحًا لإعادة البيع؛ لا تنفذ تحويل أموال تلقائيًا.
- إجمالي التقرير تقديري، ولا يمثل دفتر حسابات معتمدًا أو قائمة مالية ضريبية.
- يلزم استكمال إدارة حسابات العملاء، البريد/OTP، صلاحيات الموظفين التفصيلية، رفع الملفات الرقمية وتسليمها الآمن، ودمج الدفع والتحقق من Webhooks قبل الإطلاق التجاري.
- يفضّل قصر CORS على نطاق المتجر بعد النشر، وإضافة حدود للطلبات ومراجعة أمنية مستقلة.


## تحسينات الحماية في هذه النسخة
- لا يُسمح بإنشاء المدير الأول إلا بمفتاح `SETUP_KEY` سري.
- كلمات المرور مخزنة باستخدام PBKDF2-HMAC-SHA256 مع salt مستقل.
- جلسة الإدارة موقعة HMAC وتنتهي بعد 8 ساعات.
- تقييد محاولات تسجيل الدخول إلى 5 محاولات خلال 15 دقيقة لكل عنوان IP.
- رؤوس حماية HTTP وسياسة CSP ورفض تضمين الموقع داخل إطارات.
- CORS لا يسمح إلا بالنطاقات المسجلة في `ALLOWED_ORIGINS`.
- تقييد إعدادات المتجر العامة على مفاتيح العرض فقط.
- التحقق من عدم تكرار إرجاع كميات تتجاوز كمية الطلب، وعدم رد مبلغ أعلى من قيمة المنتجات المرتجعة.

**لا توجد حماية مطلقة.** يلزم قبل التشغيل التجاري مراجعة أمنية واختبار اختراق متخصص، وإكمال سجل التدقيق، النسخ الاحتياطي والاستعادة، إدارة جلسات الإبطال، حماية CSRF عند إضافة جلسات Cookies، التحقق من Webhooks للدفع، وسياسة صلاحيات الموظفين.



## صور المنتجات بدون تخزين ملفات
- من لوحة التحكم > المنتجات: أدخلي رابط الصورة الرئيسية وروابط الصور الإضافية.
- يجب أن تكون الروابط مباشرة وتبدأ بـ `https://`.
- لا يوجد رفع صور من الجهاز في هذه النسخة؛ أزيلت مسارات رفع وتخزين الصور وقراءتها من R2 بالكامل.
- تبقى روابط الصور محفوظة في قاعدة D1 ضمن بيانات المنتجات.
